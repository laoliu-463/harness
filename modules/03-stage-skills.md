# 四个环节的技能

## 摘要

大事的四个环节各有一个技能文件。提出问题用设计树追问，读 EverOS 时按 `rules/memory.md`。收集信息用一手来源写成带出处的记录。实操验证先做通过或失败信号，再核对真实结果，写完交给审查者审查。复盘迭代从这次对话抽教训，用户点头后才改技能，读写 EverOS 时按 `rules/memory.md`，写完交给审查者审查。交接写进第 2 个模块的任务记录。

## 1. 问题

第 2 个模块只留下四个空位。原技能里已经有做法。本模块为每个环节放一个 `SKILL.md`，不把四件事并成一个技能。

## 2. 技能

| 环节 | 技能 | 原技能 |
|---|---|---|
| 提出问题 | `skills\提出问题\SKILL.md` | 见该技能文内来源表。小事直接停，其余用设计树追问，确认后写成开场简报。读 EverOS 时按 `rules/memory.md`。 |
| 收集信息 | `skills\收集信息\SKILL.md` | 见该技能文内来源表。先写清缺的信息，再对一手来源查，同意后才进入实操验证。 |
| 实操验证 | `skills\实操验证\SKILL.md` | 见该技能文内来源表。先写判定标准，再做能重复的信号，并核对真实结果。写完交给审查者审查。 |
| 复盘迭代 | `skills\复盘迭代\SKILL.md` | 见该技能文内来源表。从这次对话抽教训，点头后才改技能。读写 EverOS 时按 `rules/memory.md`。写完交给审查者审查。不开启下一次闭环。 |

四个技能读同一份任务记录，只写自己那一节。已经确认的目标、权限和总预算不在环节中途改写。总预算换环节时接着算。用完就暂停。

## 3. 检验方法

先定通过标准。本模块现在不跑完整任务。

拿一份已经开好的大事任务记录，四个技能各做一次交接。

1. 提出问题留下一轮带推荐答案的问题。事实不是推给用户去查的。读 EverOS 时指向 `rules/memory.md`，技能里没有另一套读法。
2. 收集信息的关键结论能指到一手来源。用户还没同意时，实操验证不开始。
3. 实操验证有一条能重复的通过或失败信号，核对的是真实结果。写完这一节后，记录交给审查者审查。技能里不写审查者怎么审查。
4. 复盘迭代列出采纳和不采纳。没有用户点头，技能文件不被修改。读写 EverOS 时指向 `rules/memory.md`。写完这一节后，记录交给审查者审查。

四条都符合才算通过。试跑放在七个模块合并之后。

## 4. 边界

不重新定义大事和小事。不决定同时推进几个大目标、复盘时间和任务记录的正式目录。不另写审查者和第二大脑各管什么。不规定审查者怎么审查。不把技能分发到各个工具。不修改 `sources\` 里的克隆。
