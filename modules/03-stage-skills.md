# 四个环节的技能

## 摘要

大事的四个环节各有一个技能文件。提出问题用设计树追问。开始时按 `rules/memory.md` 第 2 节搜。用户确认简报之后才进入收集信息。收集信息用一手来源写成带出处的记录。先查知识库。剩下的未知不改变选择，或这一环的投入到了上限，就进入实操验证，并写一句理由。实操验证先做通过或失败信号，再核对真实结果，写完交给审查者审查。复盘迭代从这次对话抽教训，并看没看懂、漏查和被证明是错的来源。用户点头后才改技能。读写 EverOS 时按 `rules/memory.md`。写完交给审查者审查。交接写进第 2 个模块的任务记录。开发任务不另写工具包，到 `harness\sources\` 读对应原文。

## 1. 问题

第 2 个模块只留下四个空位。原技能里已经有做法。本模块为每个环节放一个 `SKILL.md`，不把四件事并成一个技能。

## 2. 技能

| 环节 | 技能 | 原技能 |
|---|---|---|
| 提出问题 | `skills\提出问题\SKILL.md` | 见该技能文内来源表。进入的都是大事。开始时按 `rules/memory.md` 第 2 节搜。简报经用户确认后进入收集信息。 |
| 收集信息 | `skills\收集信息\SKILL.md` | 见该技能文内来源表。先查知识库，再对一手来源查。按结束条件进入实操验证，并写一句理由。 |
| 实操验证 | `skills\实操验证\SKILL.md` | 见该技能文内来源表。先写判定标准，再做能重复的信号，并核对真实结果。写完交给审查者审查。 |
| 复盘迭代 | `skills\复盘迭代\SKILL.md` | 见该技能文内来源表。从这次对话抽教训，并看没看懂、漏查和错的来源。点头后才改技能。读写 EverOS 时按 `rules/memory.md`。写完交给审查者审查。不开启下一次闭环。 |

四个技能读同一份任务记录，只写自己那一节。已经确认的目标、权限和总预算不在环节中途改写。总预算换环节时接着算。用完就暂停。

换环节由 agent 对照该技能里已经写明的条件判断，并写一句理由。不等用户宣布换环节。条件不满足就停在这一环。这次补充不新加门槛。

## 3. 开发任务

来源是 2026-10-19 的用户决定。开发工具包并入本模块。不列技能清单，不另写工具包。

开发任务时，到 `harness\sources\` 里找对应的技能，读原文后照着做。找到的技能和 harness 规则冲突时，以 harness 规则为准。

从 do-codingwork 只搬来这四条个人规矩。

1. 本地已有匹配的仓库，就用本地的。不为同一目标另建克隆。
2. 仓库有未提交的改动时只读。不 reset，不切分支。
3. 一行明显的修复，或用户说「直接改」，跳过规划。跳过时写一句原因。
4. Grok Bot 的开发交给 Cursor 云端 agent。不把仓库克隆到用户电脑或 Grok Bot 的电脑。

去掉 do-codingwork 里的「只有用户宣布才换阶段」。换环节按上面那条，对照交接条件判断。

一个真实开发任务试跑通过后，另开 PR 删除 do-codingwork。本模块不删。

## 4. 检验方法

先定通过标准。本模块现在不跑完整任务。

拿一份已经开好的大事任务记录，四个技能各做一次交接。

1. 提出问题留下一轮带推荐答案的问题。事实不是推给用户去查的。开始时按 `rules/memory.md` 第 2 节搜。开场简报有 EverOS 查到的经验。技能里没有另一套读法。用户确认简报之后才进入收集信息。
2. 收集信息的关键结论能指到一手来源。开始时指向 `rules/memory.md` 第 2 节第 4 条。剩下的未知不改变选择，或这一环的投入到了上限，才进入实操验证，并写一句理由。
3. 实操验证有一条能重复的通过或失败信号，核对的是真实结果。写完这一节后，记录交给审查者审查。技能里不写审查者怎么审查。
4. 复盘迭代列出采纳和不采纳，并写下没看懂的次数、有没有漏查、哪些来源被证明是错的。没有用户点头，技能文件不被修改。读写 EverOS 时指向 `rules/memory.md`。写完这一节后，记录交给审查者审查。

5. 开发任务的记录写明读了 `harness\sources\` 里哪一份原文。记录里没有另一份技能清单。
6. 每次换环节有一句理由。理由不是等用户宣布。

六条都符合才算通过。试跑放在其余模块合并之后。删除 do-codingwork 要另等一个真实开发任务通过，再单独开 PR。

## 5. 边界

不重新定义大事和小事。不决定同时推进几个大目标、复盘时间和任务记录的正式目录。不另写审查者和第二大脑各管什么。不规定审查者怎么审查。不把技能分发到各个工具。不修改 `sources\` 里的克隆。不列开发技能清单。不另写工具包。不在本模块删除 do-codingwork。不把 RPI 当成默认流程。RPI 只在用户点名时用。不把 teach 并进这四个环节。teach 是学习分支。
