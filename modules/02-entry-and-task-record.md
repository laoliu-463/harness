# 入口与任务记录

## 摘要

`/harness` 先判断一件事是大事还是小事。小事直接做，不开任务记录。大事开一份任务记录，并走完整闭环。本文只定入口和任务记录的写法。四个阶段的技能、目标清单和分发不在这里。

## 1. 问题

一件事进来时，agent 需要先决定两件事。要不要走完整闭环。如果要走，中断之后从哪里接着做。

常驻规则已经写了大事和小事的界线，也写了任务记录可以直接写。还没有一份能照着填的记录，也没有一个固定入口去做这个判断。

## 2. 方法

方法分两步。先由入口分类。分类结果是大事时，再按同一份模板开记录。

分类只用常驻规则第 3 节。满足任意一条就是大事：预计要花一天以上，含有撤不回的行动，或者事前不知道怎么做。其余是小事。

小事直接做。执行的 agent 按常驻规则自己检查。不开任务记录。

大事开一份任务记录。审查者以后独立验证。审查者的具体做法不在本模块。

任务记录目录还没有定。在定下来之前，文件放在这次闭环的隔离工作树里，放在工具不会加载的位置。

### 2.1 入口

用户说出 `/harness`，或明确要求按 harness 处理一件事，入口开始工作。

入口只做分类，不开始后面的环节。分类结果和理由写给用户。用户回「是」就按该结果执行。用户改判定，就按用户的判定执行。

撤不回的行动包括花钱、对外发消息和重大人生决定。这类行动使这件事成为大事。最后那一步仍由用户决定。

### 2.2 任务记录

每件大事一份文件。启动记录在最前。四个环节各留一节，用来写交接。环节技能还没写，所以这四节现在只留空位。

```markdown
# 任务记录

## 启动记录

- 目标：
- 权限：
- 总预算：单位和数字
- 阶段预算：没有就写「未单列」
- EverOS 可写结论类型：没有就写「不写 EverOS」
- 分发：没有就写「不分发」
- 大小：大事
- 分类理由：

## 提出问题

- 开场简报：
- 用户原话：

## 收集信息

- 已确认的取舍：
- 研究范围：
- 证据与边界：
- 仍待调查：

## 实操验证

- 判定标准：
- 做法：
- 证据：
- 保留的产物：

## 复盘迭代

- 结果：
- 下一步：
- EverOS 结论：未授权则留空
```

启动记录里的目标、权限和总预算，要有用户的确认。取舍和研究范围可以后补，但进入实操验证之前必须写下用户同意的原话。

总预算换环节时接着算，不清零。收集预算用完、总预算还有余额、试验方案已经确认，才可以进入实操验证。总预算用完就暂停。

## 3. 检验方法

先写下怎样算通过，再在以后的试跑里对照。本模块现在不跑任务。

准备三条彼此不同的请求。

1. 一件小事。预期是直接做，不产生任务记录。
2. 一件含撤不回行动的大事。预期是先分类，用户确认后产生一份任务记录，启动记录填了目标、权限和总预算。
3. 一件事前不知道怎么做的大事。预期与第 2 条相同。分类理由写的是「事前不知道怎么做」，而不是「含有撤不回的行动」。

三条都符合预期，入口和模板才算通过。有一条不符合，就改入口或模板，不把结果解释成用户没说清。

试跑放在七个模块合并之后。这里只固定检验标准。

## 4. 边界

本模块不定义四个环节怎么做。不填写同时推进几个大目标。不决定复盘时间。不决定任务记录的正式目录。不把记录分发到各个工具。
