# 目标清单

## 摘要

目标清单是一份索引，只列正在考虑的大事。每项目标有状态、一句能被证伪的完成标准、粗花费、一句下一步，并指向它的任务记录。小事不进这份清单。同时能有几个「进行中」，本模块不定。

## 1. 问题

大事会并行出现。没有一份只看状态的索引，agent 会把任务记录里的细节再抄一遍，或者把小事也放进来。术语表已经定了四种状态。还没有一份能照着填的清单。

## 2. 方法

清单是索引，不是仓库。细节留在该目标的任务记录里。清单只写一句它是什么，并指向那份记录。

只有大事进清单。一两处改动、做法已经明显、也不含撤不回行动的小事，不写进行去。

每项目标使用这些字段。

- 名称。
- 状态。只用待评估、进行中、暂停、不做。不能空着。
- 完成标准。一句能被证伪的话。
- 粗花费。数量加单位，不必细到步骤。
- 下一步。一句。眼前这一步，或怎样让下一步更容易，写其中更要紧的那句。
- 任务记录。指向那份记录的位置。还没有记录时写「未开」。
- 理由。只有暂停和不做要写。

状态从待评估开始。用户确认值得做，才改为进行中，并开任务记录。做完或决定停止，改为不做，并写理由。暂时停下，改为暂停，并写理由。

本模块不决定同时有几个进行中。那一项等七个模块合并后再填。

### 模板

```markdown
# 目标清单

| 名称 | 状态 | 完成标准 | 粗花费 | 下一步 | 任务记录 | 理由 |
|---|---|---|---|---|---|---|
|  | 待评估 |  |  |  | 未开 |  |
```

## 3. 检验方法

先定通过标准。本模块现在不填真实目标。

1. 一件小事不能出现在清单里。
2. 一件大事以待评估进入。完成标准能被证伪，粗花费有单位，任务记录写「未开」。
3. 改为暂停或不做时，理由不是空的。
4. 改为进行中时，指向一份任务记录，清单里不复制那份记录的环节内容。

四条都符合才算通过。试跑放在七个模块合并之后。

## 4. 边界

不重新定义大事和小事。不填写同时进行几个大目标。不改任务记录模板。不开启闭环。不分发。
